The NVIDIA NeMo Fabric `nemo-fabric` CLI is an experimental command-line interface for exploring agent execution from your terminal. Use it to discover built-in presets and maintained examples, inspect their configuration, diagnose requirements, and run a request through a selected harness.

Start with the credential-free `scripted` preset to try execution, then explore a supported harness with its required dependencies and credentials. When you are ready to build an application, the CLI can scaffold editable Python or Rust source from an example. Applications use the SDK or Rust library directly.

The Python SDK does not install this CLI. Start with [Install](install.mdx), then choose a workflow:

| Goal | Guide |
| --- | --- |
| Verify execution without model credentials | [Presets](presets.mdx), using `scripted` |
| Inspect or run a supported harness configuration | [Presets](presets.mdx) |
| Explore maintained task and harness variants | [Examples](examples.mdx) |
| Generate code to edit in your own application | [Scaffold an Application](scaffold.mdx) |

## CLI Boundaries

The CLI has the following boundaries:

- Every preset and example variant constructs a complete typed `FabricConfig`.
- Examples reuse preset constructors and one shared workspace and skill asset
  tree; Python and Rust launchers do not duplicate those definitions.
- NeMo Fabric does not discover or persist YAML, TOML, or JSON agent configuration.
- JSON request payloads and harness-generated files are runtime inputs and
  outputs, not NeMo Fabric configuration sources.
- The CLI is not an application API, scheduler, evaluation framework, or
  production deployment interface.

Current lifecycle commands are `plan`, `doctor`, and `run`. Use `preset list`
and `preset show` to discover presets. Use `example list` and `example show` to
discover examples.
