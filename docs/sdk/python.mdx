The NVIDIA NeMo Fabric Python SDK lets your application configure and run supported agent harnesses and custom agents through one interface. Use it to embed agent execution in your own application, evaluation workflow, or service while keeping control of task scheduling and result handling.

The basic workflow is to describe an agent with a typed configuration, submit a request, and read its result. You can keep a runtime open for related turns, connect skills and MCP tools, or add streaming and diagnostics where the selected adapter supports them. Start with the [Quickstart](../getting-started/quickstart-overview.mdx) for a working application, then use the guides below to extend it.

- [Quickstart](../getting-started/quickstart.mdx): install a harness and run a first agent.

## Execution Model

`FabricConfig` describes the agent. To execute, use one of these lifecycle paths:

| Need | API | Lifecycle |
| --- | --- | --- |
| One independent request | `await Fabric().run(config, input=...)` | Start, invoke once, collect the result, and attempt shutdown |
| Several related turns | `await Fabric().start_runtime(config)` | Keep the returned runtime and invoke it in order; use `async with` for shutdown |

`Fabric` is a reusable facade and does not need cleanup. A `Runtime` owns stateful execution. Each runtime accepts one active invocation at a time; applications create independent runtimes for parallel work. A runtime can use a native SDK, child process, or shared service without changing the consumer lifecycle.

Applications own task scheduling, concurrency limits, retries, and recovery policy. An adapter owns harness-native behavior. A common API does not imply identical capabilities across adapters.
