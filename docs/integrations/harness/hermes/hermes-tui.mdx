Start with [hermes.mdx](./hermes.mdx) for shared setup and an overview of all four invocation paths.

NVIDIA NeMo Fabric's terminal path attaches a prebuilt Hermes terminal renderer to a runtime-owned TUI service. This fourth client path shares the dashboard's execution backend; it does not create a fourth backend or invoke the embedded SDK agent.

## Installation

Complete the [shared installation](./hermes.mdx#install-the-adapter) first. Terminal attachment additionally requires:

- **Backend dependencies:** FastAPI, Uvicorn, and the other dependencies in pinned Hermes's `web` extra. The repository's Python 3.14 `just install-hermes-agent` recipe already provides them.
- **Client assets:** The built terminal renderer and a supported Node runtime on the machine running the client. Terminal-only mode needs no browser assets.
- **Host:** POSIX, for the managed backend and terminal attachment helper.

For a separately prepared Hermes environment, set `ADAPTER_PYTHON` to its interpreter and `HERMES_AGENT_CHECKOUT` to your pinned v0.22.5 source checkout, then install the web extra:

```bash
uv pip install --python "$ADAPTER_PYTHON" --editable "${HERMES_AGENT_CHECKOUT}[web]"
```

Follow the [frontend setup commands](../../../../examples/interfaces/README.md#build-the-tui-frontends) to build the terminal bundle. For terminal-only use, skip the browser build and `HERMES_WEB_DIST` setting. If the dashboard backend is already enabled, reuse it; terminal attachment does not require another backend installation.

The helper uses `HERMES_TUI_DIR/dist/entry.js` when configured; otherwise it looks for `hermes_cli/tui_dist/entry.js` or the pinned checkout's `ui-tui/dist/entry.js`. `HERMES_NODE` can select an executable Node runtime; otherwise it uses Node from `PATH`. It does not build or install missing assets.

## Configuration

Combine normalized model/workspace/Relay configuration with these harness settings:

```python
settings = {
    "sdk": {"enabled": False},
    "interfaces": {"terminal": {"port": 9119}},
}
```

Terminal-only mode starts `hermes serve --isolated`, which runs the backend without serving the browser dashboard. If dashboard is also enabled, give it the same port: the terminal attaches to that existing service instead. API, if enabled, needs a distinct port. SDK remains enabled by default unless explicitly disabled.

## Attach and Detach

After readiness, the adapter publishes owner-only attachment files under `<artifact root>/.fabric/hermes/runtimes/<runtime-id>/interfaces/`: `tui.json` describes the port/mode/workspace, and `tui.token` contains a separate TUI credential. The [runnable example](../../../../examples/interfaces/README.md#4-terminal-tui) prints the exact attachment command using that runtime's descriptor.

Run the helper from an interactive terminal with the Hermes interpreter. It validates the files and authenticated backend, then executes the prebuilt renderer with an explicit WebSocket attachment URL. The token is supplied through the environment, not command arguments. It never falls back to spawning an unmanaged backend. The API token is not used for TUI attachment.

Terminal clients start independent native conversations by default. Detaching leaves the backend/runtime running; it is not an instruction to cancel a turn. The runtime owner stops its backend and removes attachment files. Same-conversation multi-client control and detach during active work require explicit qualification; use the runtime owner's stop action for final cleanup.

## Results, Relay, and Testing

Terminal output is native; it is not a normalized NeMo Fabric `RunResult`. With Relay enabled, managed agent turns finalize/flush native segments without deleting conversation history. Verify populated ATIF tool steps after each completed turn without detaching or stopping the runtime.

Use the [TUI example](../../../../examples/interfaces/README.md#4-terminal-tui) for manual input, repeated turns, and artifact inspection. Read the [shared limitations](./hermes.mdx#limitations-and-planned-work), including approval policy, shared filesystem access, native activity visibility, and cleanup limits. The initial attachment helper supports local loopback clients; remote discovery and credential transport are outside this iteration.
