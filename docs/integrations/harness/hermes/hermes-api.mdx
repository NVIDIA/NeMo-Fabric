Start with [hermes.mdx](./hermes.mdx) for shared setup and an overview of all four invocation paths.

NVIDIA NeMo Fabric can host Hermes's native HTTP API as a managed `hermes gateway run` process. Requests execute through native agents, independently of the embedded SDK and TUI backend. The HTTP service uses `aiohttp`; it is separate from the FastAPI dashboard service.

## Installation

Complete the [shared installation](./hermes.mdx#install-the-adapter). Install the pinned Hermes messaging dependencies providing `aiohttp` in the adapter interpreter. The repository's `just install-hermes-agent` recipe already includes them. API-only use needs no browser or terminal frontend. Native interfaces currently require POSIX.

## Configuration

Combine the normalized model/workspace configuration from the [SDK guide](./hermes-sdk.mdx#configure-the-adapter) with these harness settings:

```python
settings = {
    "sdk": {"enabled": False},
    "interfaces": {"api": {"port": 8642}},
}
```

This disables embedded SDK execution explicitly. Omit `sdk` to retain its default eager startup. The API is off unless selected; selecting it does not start a dashboard or terminal backend. Model, instructions, tools, and Relay remain in normalized configuration fields.

## Authentication

The API server binds to `127.0.0.1` at its configured port. After every enabled interface passes readiness, the adapter writes a per-start bearer token with mode `0600` to:

```text
<artifact root>/.fabric/hermes/runtimes/<runtime-id>/interfaces/api.token
```

Clients calling the native API must read the generated token file and include `Authorization: Bearer <token>` in each HTTP request. Only the API gateway child receives it in its environment. Processes running as the runtime's user, including agent tools, can read the token file.

## Requests, Clients, and Conversations

The pinned native service includes OpenAI-compatible chat completions and responses, native run/session endpoints, and health diagnostics. The managed chat-completions path has end-to-end evidence; other native routes need separate qualification before relying on equivalent behavior.

Multiple clients can connect. Use native session/conversation mechanisms for separate histories; clients share the runtime's workspace, tools, home, and per-start bearer credential. A common credential does not provide per-user isolation. Concurrent workload qualification is separate from accepting multiple connections.

Native requests do not pass through `Runtime.invoke()` and do not return NeMo Fabric `RunResult` objects. Shared configuration does not attach them to the embedded SDK conversation.

## Relay Trajectories

With Relay enabled, managed API turns finalize and flush a segment when native execution returns. ATIF is available per turn without deleting native history; subsequent turns can continue the conversation and produce new segments. Check actual ATOF events and ATIF tool steps, since export failures are logged and do not replace the response.

## Health, Testing, and Limitations

Startup probes `/health`. Runtime checks additionally observe the owned process and its endpoint; they do not execute a model request. Hermes exposes authenticated `/health/detailed`, run status, and persisted sessions, but these are not a unified inventory of live agents in NeMo Fabric.

See the [API example](../../../../examples/interfaces/README.md#hermes-api-example) for requests and trajectory inspection, and the [shared limitations](./hermes.mdx#limitations-and-planned-work) for lifecycle and artifact boundaries.
