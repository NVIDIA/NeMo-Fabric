Use the NeMo Fabric Remote Agent adapter to call an OpenClaw Gateway over HTTP. For OpenClaw Gateway API details, refer to the [OpenClaw OpenAI HTTP
API](https://docs.openclaw.ai/gateway/openai-http-api).

For general Remote Agent settings, refer to [Use the Remote Agent
Adapter](./remote-agent.mdx).

Before you start, complete the following steps:

1. [Install OpenClaw](https://docs.openclaw.ai/install) and configure a working
   default agent and model.
2. Enable the Chat Completions API, validate the configuration, and restart the
   Gateway:

   ```bash
   openclaw config set gateway.http.endpoints.chatCompletions.enabled true --strict-json
   openclaw config validate
   openclaw gateway restart
   ```

3. Generate a Gateway token, restart the Gateway, and display the token:

   ```bash
   openclaw doctor --generate-gateway-token
   openclaw gateway restart
   openclaw gateway auth-token --show
   ```

   Copy the displayed token into the shell that runs the Python example:

   ```bash
   export OPENCLAW_GATEWAY_TOKEN="<gateway-token>"
   ```

   Treat this token like an administrator password. Do not share it or expose
   the Gateway to the public internet.

Install the Remote Agent adapter:

```bash
pip install "nemo-fabric[remote-agent]"
```

The following Python code snippet demonstrates how to run a prompt through the Remote Agent adapter to an OpenClaw Gateway backend. This code assumes a running Gateway listening on the default local address `http://127.0.0.1:18789`.

```python
import asyncio
import pprint

from nemo_fabric import (
    Fabric,
    FabricConfig,
    HarnessConfig,
    MetadataConfig,
    ModelConfig,
    RuntimeConfig,
)


config = FabricConfig(
    metadata=MetadataConfig(name="openclaw-remote-agent"),
    harness=HarnessConfig(
        adapter_id="nvidia.fabric.remote-agent",
        settings={
            "base_url": "http://127.0.0.1:18789/v1",
            "api_type": "openai-completions",
        },
    ),
    models={
        "default": ModelConfig(
            provider="openclaw",
            model="openclaw/default",
            api_key_env="OPENCLAW_GATEWAY_TOKEN",
        )
    },
    runtime=RuntimeConfig(artifacts="./artifacts"),
)

result = asyncio.run(Fabric().run(config, input="Who are you?"))

if result["status"] == "failed":
    pprint.pprint(result.to_mapping())
else:
    print(result.output.response)
```

The `model` value `openclaw/default` selects OpenClaw's configured default
agent. It does not select the model that OpenClaw sends to its provider.

> *Note:*
>
> In the above example the Remote Agent adapter communicates with an OpenClaw Gateway running locally over the loopback IP address `127.0.0.1`. When communicating with a remote Gateway, use HTTPS to ensure the Gateway token is not transmitted in plaintext. Refer to https://docs.openclaw.ai/gateway/stable-https-url for more information.

## Troubleshoot Common Problems

Use the following table to fix common setup problems.

| Problem | Likely cause | Fix |
| --- | --- | --- |
| `404 Not Found` | The Chat Completions endpoint is disabled, or `base_url` does not end in `/v1`. | Enable `gateway.http.endpoints.chatCompletions` and use `http://<host>:<port>/v1`. |
| `401 Unauthorized` | The token is missing or does not match the Gateway token. | Run `openclaw gateway auth-token --show` on the Gateway host and set `OPENCLAW_GATEWAY_TOKEN` again. |
| Connection refused | The Gateway is stopped, uses another port, or is not reachable from the Python host. | Start the Gateway and check the address and port. |
| OpenClaw returns an agent error | The selected OpenClaw agent or its model is not ready. | Run `openclaw models status` on the Gateway host and fix the reported model or credential problem. |
