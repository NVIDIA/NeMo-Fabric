Use the `nvidia.fabric.opencode` adapter to run tasks with the OpenCode 2 SDK.
Each NVIDIA NeMo Fabric runtime starts one embedded OpenCode host and session.

## Install the Adapter

OpenCode adapter processes require Bun 1.4.2 or later on `PATH`.

To use a published adapter release, install the npm adapter and the compatible
OpenCode SDK in the project that owns the NeMo Fabric configuration:

```bash
npm install nemo-fabric-adapters-opencode @opencode/core@2.0.23 @opencode/sdk@2.0.23
```

OpenCode Core and the OpenCode SDK are optional peers, exact-pinned to the
supported OpenCode release. Installing the adapter alone does not install
either package. Starting the adapter without the compatible packages returns
`opencode_harness_unavailable`.

OpenCode 2.0.23 does not support npm's `install-strategy=nested`. The documented
command requires the default npm hoisted layout.

For source development, install the checked-out adapter workspace and its
pinned SDK from the repository root, then build the generated adapter CLI:

```bash
just install-typescript-opencode
npm run build --prefix adapter-contract/typescript
npm run build --prefix adapters/typescript --workspace nemo-fabric-adapters-common
npm run build --prefix adapters/typescript --workspace nemo-fabric-adapters-opencode
```

## Configure the Adapter

Select the OpenCode integration and point discovery at the adapter descriptor.
The following example uses the descriptor from an installed npm package:

```python
from nemo_fabric import DiscoveryConfig, FabricConfig, HarnessConfig
from nemo_fabric import MetadataConfig, ModelConfig

config = FabricConfig(
    metadata=MetadataConfig(name="opencode-review"),
    discovery=DiscoveryConfig(
        local_paths=[
            "./node_modules/nemo-fabric-adapters-opencode/opencode.fabric-adapter.json"
        ]
    ),
    harness=HarnessConfig(adapter_id="nvidia.fabric.opencode"),
    models={
        "default": ModelConfig(
            provider="nvidia",
            model="nvidia/nemotron-3.5-nano-30b-a3b",
            api_key_env="NVIDIA_API_KEY",
            base_url="https://integrate.api.nvidia.com/v1",
        )
    },
)
```

This example uses NVIDIA's hosted Nemotron 3.5 Nano model. Set
`NVIDIA_API_KEY` before starting the runtime.

For a source build, set `discovery.local_paths` to
`adapters/typescript/opencode/opencode.fabric-adapter.json` instead. The build
commands above create the descriptor's `dist/cli.js` runner.

## Supported Configuration

The adapter supports the following configuration:

- **Models:** Selects the `default` role, or the only configured role.
  `api_key_env` may use any portable environment-variable name. When no
  endpoint is configured, the provider and model must be supported by the
  installed OpenCode SDK.
- **Instructions:** Supports `instructions.system` with `mode: replace`.
  A replacement instruction replaces OpenCode's base prompt. OpenCode may still
  append runtime context.
- **Skills:** Each `skills.paths` entry must be a directory containing `SKILL.md`.
  Startup verifies that only those `SKILL.md` files load and that names are unique.
- **MCP:** Supports `stdio` and `streamable-http`. Startup fails if a configured
  server cannot connect.

### Model Endpoints

To route model requests through a local or company-hosted endpoint, set
`base_url`. The endpoint must implement the OpenAI-compatible Chat Completions
protocol. It is a model-provider endpoint, not the address of a remote
OpenCode server.

HTTPS is required by default, except for loopback HTTP. For a trusted Docker or Kubernetes gateway, set `harness.settings.insecure_http_model_hosts` to the exact hostnames that can receive HTTP model requests. Entries contain only hostnames or IPv4 addresses, without schemes, ports, paths, or wildcards. Matching ignores case and a trailing DNS dot, and permits any port or path on the listed host. The adapter does not resolve DNS to infer trust. Allowlisted HTTP endpoints receive model credentials and prompt content over an unencrypted connection. This setting applies only to model endpoints; MCP endpoint restrictions are unchanged.

For example, allow the gateway hosts used by your deployment:

```yaml
harness:
  settings:
    insecure_http_model_hosts:
      - host.docker.internal
      - release-nhx-api
      - gateway.namespace.svc.cluster.local
```

The adapter removes OpenCode's
`prompt_cache_key` extension for configured endpoints, so providers that
reject that OpenAI-specific field can still use the core protocol. The proxy
buffers and rewrites request bodies up to 16 MiB. Larger requests receive HTTP
413 rather than consuming unbounded adapter memory.

`temperature` and `top_p` are supported only with `base_url`.

To configure a loopback OpenAI-compatible endpoint for development, set
`base_url` as follows:

```python
config.models["default"].base_url = "http://127.0.0.1:8080/v1"
```

### MCP Configuration

Streamable-HTTP servers may define headers but not command arguments. Stdio
servers may define command arguments and environment variables but not HTTP
headers.

Streamable-HTTP server URLs require HTTPS except for loopback development
endpoints.

Header values may reference `${NAME}`. Resolution checks `environment.env`
first, then the parent process environment. Unresolved references fail startup.
For MCP credentials, prefer parent-only variables so they are used to construct
the header without being added to OpenCode's tool environment.

SSE, MCP authentication objects, and per-server tool filters are unsupported.
MCP elicitation is also unsupported. Configure only non-interactive MCP servers as
NeMo Fabric cannot reply to an elicitation request, so it can block an
invocation until its configured timeout.

### Runtime Behavior

The embedded session keeps the Fabric workspace as its working location, but
does not load ambient OpenCode project or user configuration and instructions
from that workspace or the host home directory.

At runtime, OpenCode receives only required operating-system variables,
explicit NeMo Fabric `environment.env` values, variables named by
`environment.env_names`, and the selected model credential. Other variables
inherited by the NeMo Fabric process are not exposed to OpenCode.

The adapter is non-interactive. It denies OpenCode's direct `read` permission
for `.env` files (except `.env.example`), access outside the workspace, or
follow-up questions rather than waiting for an approval that NeMo Fabric cannot
supply. These rules are not a filesystem sandbox and do not prevent shell tools
from reading files in the workspace.

The adapter accepts plain-text input and returns the final response in
`output.response`. Streaming, Relay, tool policy, NeMo Fabric subagent
configuration, provider-specific model settings, and `max_tokens` are not
supported. The model can still call OpenCode's built-in `subagent` tool, and
the adapter counts that usage as described below.

## Understand the Runtime Lifecycle

The adapter runs in a persistent Bun process. `start` creates one embedded
OpenCode host and one OpenCode session for the NeMo Fabric runtime. Ordered
plain-text invocations reuse that session and its conversation history. A
successful result has `output.response`. `stop` removes the OpenCode session
and closes the embedded host.

Each result's `usage` is the growth of OpenCode's session token counters
during the invocation, including context compaction calls. The adapter adds
the growth of every subagent session below the NeMo Fabric session, because a
subagent runs in a child session with its own counters. `input_tokens`
includes cache reads and cache writes, with `input_tokens_include_cache` set to
`true` and the cache reads in `cached_input_tokens`. `output_tokens` includes
reasoning tokens, and `total_tokens` is their sum. The adapter does not report
OpenCode's catalog-rate cost as `cost_usd`.

The adapter checks new assistant and compaction records that the invocation
added to each session's full message history. OpenCode stores a count the provider
left out as 0. A real model call always has input, so a call with no input
tokens leaves `input_tokens` unknown, and a call with no output or reasoning
tokens leaves `output_tokens` unknown. Either case also leaves out
`total_tokens`, and so does a session counter that is missing or goes down. A
`total_tokens` past JavaScript's safe integer range is left out.

Counter growth from earlier background work is excluded. Usage remains unknown
when a delayed completion or resumed child prevents reliable attribution. A
result has no `usage` when a model call or compaction failed without recorded
usage, when a subagent session that the invocation started was still running
when it ended, when the NeMo Fabric session was already running when it started,
when the invocation continued a subagent that was still running from earlier
work, when it made a model call after the completion notice of a subagent that
existed before the invocation, or when the counters or message history cannot
be read.

OpenCode replaces individual missing counters with zero before the adapter sees
them. Those omissions and internal retries without recorded usage can still
undercount totals.

```mermaid
flowchart LR
  Fabric["Fabric runtime"] -->|"NDJSON over stdio"| Adapter
  subgraph Bun["One persistent Bun adapter process"]
    Adapter["OpenCode adapter"] --> Client["OpenCode SDK client"]
    Client -->|"in-memory fetch (no TCP)"| Host["Embedded OpenCode host"]
    Host --> Session["One OpenCode session"]
    Host -->|"when models.base_url is configured"| Proxy["Loopback compatibility proxy"]
  end
  Proxy --> Provider["Model-provider endpoint"]
  Host -->|"otherwise"| NativeProvider["OpenCode native provider"]
```

When OpenCode reports files changed by an invocation and the runtime has an
artifact root, the adapter writes the combined diff to a runtime- and
invocation-scoped path beneath `opencode/` and returns it as a `patch` artifact.
Without an artifact root, it returns no patch artifact.

Create a new runtime to change the selected model or workspace.
