NVIDIA NeMo Fabric resolves each `skills.paths` entry in the task environment when the adapter starts. An entry names one skill or a folder of skills.

## How NeMo Fabric Resolves an Entry

The following rules apply to each entry:

- An entry that contains `SKILL.md` is one skill.
- Otherwise, each folder directly inside the entry that contains `SKILL.md` is a skill. Other files and folders, including folders that cannot be read, are ignored.
- An entry that exists but holds no skills, such as a new, empty volume, loads nothing.
- Start fails when an entry does not exist or is not a folder, when an entry without `SKILL.md` cannot be listed, when a skill's `SKILL.md` cannot be read, or when two resolved skills share a name. The error names the entry or both skill folders.
- The same folder listed through several entries loads once.
- A skill's name is the `name` field of its `SKILL.md` front matter, or its folder name when the front matter has none.

Relative entries resolve against the agent's base directory. NeMo Fabric does not expand `~` or environment variables such as `${VAR}`.

The OpenClaw and Hermes Agent adapters follow these rules. They pass each resolved skill folder to the harness's native skill loader. Other adapters that accept `skills.paths` still require each entry to contain `SKILL.md`; refer to each adapter's guide.

## Harness Differences

NeMo Fabric decides which folders are skills, but the harness loads them, and it can find more skills or name them differently:

| Situation | What Happens |
| --- | --- |
| A skill folder contains other skill folders | Hermes Agent also loads the nested skills. It searches every folder below a skill except `references`, `templates`, `assets`, and `scripts`. OpenClaw loads only the skill folder. |
| Two skills share a name | NeMo Fabric's duplicate check covers only the skills it resolves from `skills.paths`. It does not see nested skills that Hermes Agent loads or skills that a harness loads from its own folders. |
| A skill's name matches another skill's folder name | Hermes Agent looks a skill up by its name, its folder name, and its path. The skill is ambiguous, and Hermes Agent does not load it. OpenClaw loads both skills. |
| A skill's file is `skill.md` or uses another case | On a case-insensitive file system, NeMo Fabric accepts the folder as a skill. Hermes Agent requires exactly `SKILL.md` and does not load the skill. |
| A skill's name is longer than 64 characters | Hermes Agent cuts the name to 64 characters, so two names that share their first 64 characters collide. |
| A folder of skills contains a hidden folder, such as `.archive` | NeMo Fabric loads a hidden folder that contains `SKILL.md` as a skill. Hermes Agent's own scans skip folders such as `.archive`, `.git`, and `.hub`. |
| A Hermes Agent configuration used relative paths, `~`, or `${VAR}` | Hermes Agent's own `skills.external_dirs` resolves relative paths against the Hermes home and expands `~` and `${VAR}`; NeMo Fabric does neither. |

To avoid these differences, keep one skill per folder, do not nest skill folders, give each skill a name that differs from every skill folder name, and name the file `SKILL.md`.
